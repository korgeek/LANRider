# LANRider

**Run locally. Race together.**

[English README](README.md)

LANRider는 개인 LAN 파티에서 즐기는 자체 호스팅 브라우저 레이싱 게임입니다. 소프트웨어에는 MIT 라이선스가 적용되며 프로젝트 아트와 음악에는 별도 조건이 적용됩니다. 프로젝트 아트와 음악은 각 이용 조건에 따라 사용할 수 있고 GitHub에서 이 저장소를 포크할 수 있습니다. 다만 GitHub 포크 외에 에셋을 별도로 또는 다른 제품에 포함해 재판매·재배포할 수는 없습니다. 자세한 내용은 [에셋 이용 조건](public/assets/licenses.md)을 확인하세요.

처음에는 로컬에서 실행한다는 뜻으로 **LocalHostRIDER**라고 불렀습니다. 이후 같은 LAN에서 함께 달리는 게임이라는 의미를 담아 **LANRider**로 이름을 정했습니다. 일부 스크린샷에는 당시의 이름이 남아 있습니다.

## 빠른 실행

### Node.js로 간단히 실행

Docker 없이 Node.js 24를 설치한 뒤 프로젝트 폴더에서 실행할 수 있습니다.

```sh
npm ci
npm start
```

데스크톱 브라우저에서 [localhost:3000](http://localhost:3000)을 열고 게임을 확인합니다. 서버는 Ctrl+C로 종료합니다. 자동 테스트는 서버를 종료한 뒤 또는 별도 터미널에서 `npm test`로 실행할 수 있습니다.

### Docker로 실행

Docker를 설치한 뒤 프로젝트 폴더에서 다음 명령을 실행합니다.

```sh
docker build -t lanrider .
docker run --rm --name lanrider -p 3000:3000 lanrider
```

데스크톱 브라우저에서 [localhost:3000](http://localhost:3000)을 엽니다. 서버는 Ctrl+C로 종료합니다.

Docker를 사내 LAN이나 리버스 프록시 뒤에서 실행하면 참가자가 접속할 주소를 지정합니다.

```sh
docker run --rm --name lanrider -p 3000:3000 -e "PUBLIC_ORIGIN=http://<서버-LAN-IP>:3000" lanrider
```

자리표시자를 실제 서버 주소로 바꿉니다. `PUBLIC_ORIGIN`에는 외부로 연결한 포트까지 포함한 HTTP(S) 주소를 지정하며, 초대 링크에 컨테이너 내부 IP가 들어가는 것을 방지합니다.

Docker Hub 연결이 차단된 환경에서는 `NODE_IMAGE`로 로컬에 캐시된 이미지나 조직에서 승인한 Node.js 24 이미지를 선택합니다. 아래는 해당 이미지가 이미 로컬에 있을 때의 예시입니다.

```sh
docker build --build-arg NODE_IMAGE=node:24.20.0-bookworm-slim -t lanrider .
```

네트워크 정책을 우회하지 않습니다. 첫 빌드에는 허용된 레지스트리나 빌드 캐시에서 npm 의존성 3개를 가져올 수 있어야 합니다. 완성된 이미지를 실행할 때는 의존성을 다운로드하지 않습니다.

### LAN 접속

같은 LAN의 친구에게는 `http://<서버-LAN-IP>:3000`과 방 코드 또는 초대 링크를 공유합니다. `localhost`는 브라우저를 여는 자신의 컴퓨터를 뜻합니다. 다른 사람은 서버 컴퓨터의 접속 가능한 LAN 주소를 사용해야 합니다. 다른 PC에서 접속되지 않으면 먼저 서버 PC의 OS 방화벽이 Node.js 또는 사용하는 TCP 포트(기본 3000번)의 LAN 접근을 막고 있지 않은지 확인하세요. 필요한 경우 조직의 네트워크 정책에 따라 신뢰할 수 있는 네트워크에서만 허용합니다. 방화벽 외에도 네트워크의 기기 간 통신 차단이나 잘못된 서버 주소가 원인일 수 있습니다.

## 짧게 한 경기

- 첫 방문에는 드라이버 이름을 입력하고 차량 8종과 서킷 3종 중에서 선택해 혼자 연습하거나 방을 만듭니다. 다음 방문에는 저장한 이름을 사용합니다.
- 방 코드나 초대 링크를 공유합니다. 방마다 주행 4명과 관전·대기 16명을 지원합니다.
- 준비를 마친 뒤 방장이 출발시킵니다. 코스 선택 옆에서 초보 3·5·7랩, 상급 1·3·5랩을 고릅니다. 첫 완주 후 아직 달리는 참가자에게 최대 10초를 주며, 모두 완주하면 즉시 결과로 넘어갑니다. 혼자 연습할 때도 완주 즉시 종료됩니다.
- 준비하지 않은 참가자가 있어도 방장이 확인 후 강제 시작할 수 있습니다. 모두에게 5초를 안내한 뒤 서버가 출전자를 준비 완료로 전환하고 기존 출발 신호를 시작합니다. 방장이 나가면 강제 시작 예약은 취소됩니다.
- 특정 드라이버를 관전하거나 자동으로 선두를 따라갑니다. 대기자는 다음 경기에 대기열 순서로 합류합니다.
- 경기 사이에 차량을 바꿀 수 있습니다. 결과 화면에서 방장이 준비하면 10초 재경기 타이머가 시작되고, 모두 준비하면 바로 3초 출발 카운트다운으로 넘어갑니다. 방장이 준비를 취소하면 자동 시작도 취소됩니다.

| 키 | 동작 |
| --- | --- |
| W / ↑ | 가속 |
| S / ↓ | 제동 / 후진 |
| A, D / ←, → | 조향 |
| Shift | 드리프트 및 부스트 충전 |
| Space | 충전된 부스트 사용 |
| R | 트랙으로 복귀 |
| F3 | 주행·네트워크·음악 진단과 충돌 박스 표시 전환 |

GO 출발 신호에 맞춰 W / ↑를 새로 누르면 게이지 차감 없이 0.9초 출발 부스트가 걸립니다. 미리 누른 채 기다리면 일반 가속으로 출발하며, 키를 뗐다가 타이밍에 맞춰 다시 누르면 보너스를 받을 수 있습니다.

한국어와 영어 UI를 지원합니다. 설정에서 그래픽 품질과 소리를 조절할 수 있으며, 지원하는 환경에서는 선택한 설정을 브라우저 저장소에 보관합니다.

## 인터넷 서버 운영 안내

LANRider는 신뢰할 수 있는 사람들과 LAN에서 즐기도록 만들고 테스트했습니다. 지금까지 기록된 검증은 로컬과 Docker 환경 중심이며, 여러 실제 PC에서의 접속과 인터넷 WAN 플레이는 아직 검증되지 않았습니다. **인터넷 공개 서버 운영은 이 프로젝트의 지원 범위가 아니며, 공개 운영으로 발생하는 문제는 앞으로도 별도로 대응하거나 후속 관리하지 않습니다.**

인터넷에 서버를 공개하면 다음과 같은 문제가 발생할 수 있습니다.

- **소켓 점유와 서비스 거부:** 한 사용자가 전체 WebSocket 연결 슬롯 128개를 차지해 다른 사람의 접속을 막을 수 있습니다. 반복 연결이나 대량 요청으로 서버 자원이 소진될 수도 있습니다.
- **원치 않는 방 참가:** 로그인과 접근 제어가 없어 서버에 접속할 수 있는 사람은 방 목록을 보고 참가할 수 있습니다.
- **다른 사이트의 WebSocket 연결:** 브라우저 Origin을 검사하지 않아, 연결 가능한 환경에서는 다른 웹사이트에서도 방 목록 조회나 참가를 시도할 수 있습니다.
- **통신 노출:** 기본 서버는 HTTP를 사용하므로 별도 TLS 보호 없이 인터넷에 노출하면 방 코드와 닉네임 등의 통신 내용이 제3자에게 노출되거나 변조될 수 있습니다.
- **부하와 경기 손실:** 단일 프로세스에서 방과 경기를 관리하므로 많은 요청이나 네트워크 지연은 플레이에 영향을 줄 수 있습니다. 서버가 종료되거나 재시작되면 진행 중인 방과 경기도 사라집니다.

`PUBLIC_ORIGIN`은 초대 링크 주소만 지정하며 접근을 보호하지 않습니다. 공개 운영을 선택한다면 접근 제어, 허용 Origin 검사, 연결·요청 제한, TLS 등은 운영자가 직접 검토하고 마련해야 합니다. 이 목록은 모든 위험을 망라하지 않습니다.

## 오프라인 동작과 한계

Docker 이미지 또는 npm 의존성을 받은 뒤에는 핵심 경주와 로컬 에셋을 인터넷 없이 사용할 수 있습니다. 방장 브라우저는 타임존으로 추정한 대표 도시를 사용해 외부 Open-Meteo 운량 조회를 시도할 수 있습니다. 위치 권한은 요청하지 않습니다. 날씨 조회가 실패해도 기본 구름으로 경주를 계속하며, 천체 계산과 별 목록은 로컬에서 동작합니다.

작은 LAN 중심 MVP입니다. 계정, 영구 기록, 매치메이킹 서비스, 다중 서버 방 저장소는 없습니다. 브라우저 백그라운드 제한, 기기 성능, 네트워크 지연은 여전히 플레이에 영향을 줄 수 있습니다. 인터넷 공개에는 별도 라우팅과 배포 작업이 필요하며, 여기서 공개 배포나 WAN 검증을 완료했다고 주장하지 않습니다.

## 검사 실행

```sh
npm test
node tools/qa/change-server-check.mjs --dnf
node tools/qa/change-server-check.mjs --dnf --auto-timeout
```

자동 테스트는 공유 물리, 경기 상태, 클라이언트 예측, 프로토콜 검증, 오디오 동작, 렌더링 계약을 다룹니다. 시간이 더 걸리는 독립 검사는 임시 loopback 서버를 시작하고 WebSocket으로 실제 물리 시뮬레이션을 구동해 완주 제한 시간과 재경기 흐름을 확인합니다. 여러 기기의 플레이테스트나 WAN 접속 검증을 대신하지는 않습니다.

## 저장소 구성

```text
server.js          HTTP 및 서버 권위 WebSocket 서버
shared/            물리, 경기 규칙과 하늘 계산
public/            브라우저 앱과 실행 에셋
test/              현재 기능의 자동 회귀 테스트
tools/qa/          독립 경기 통합 검사
```

로컬 `_archive/`의 백업과 작업 원본은 Git과 Docker에서 제외합니다. `test/`는 개발용 테스트이며 실행용 Docker 이미지에는 포함하지 않습니다.

프로젝트가 시작된 이야기와 자세한 물리·네트워크·오디오 구현은 [개발 이야기](docs/development.ko.md)에서 확인할 수 있습니다. 새로운 코스나 차량을 만들 때는 [코스 추가 가이드](docs/course-guide.ko.md)와 [차량 추가 가이드](docs/vehicle-guide.ko.md)를, 음악을 교체할 때는 [음악 교체 안내](AGENTS.md#updating-music)를 참고하세요.
