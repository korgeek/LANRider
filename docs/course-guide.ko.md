# 코스 추가 가이드

이 문서는 현재 LANRider의 코드 구조를 기준으로 새 코스를 추가하고 검증하는 방법을 정리합니다. 코스는 화면에 보이는 길만이 아니라 서버와 클라이언트가 함께 사용하는 주행 경로, 랩 판정, 장면과 방 선택까지 함께 연결해야 합니다.

## 1. 코스 구상과 경로 만들기

먼저 코스의 이름, 대략적인 형태와 난이도, 진행 방향, 출발 직선, 랩 수와 주변 풍경을 정합니다. 기존 세 코스와 구분되는 특징을 정하되, 네 대의 출발 공간과 차량이 실제로 통과할 수 있는 도로 폭을 확보합니다.

[`shared/game.js`](../shared/game.js)의 `TRACKS`에 고유한 ID와 이름, `[x, z]` 제어점을 추가하고 같은 ID를 `LAP_OPTIONS`에도 등록합니다. 기존 `technical`과 `mandalika`가 출발점 기준 좌표 변환을 포함한 예시입니다. 필요에 따라 해당 코스의 시작점과 스케일을 정하되 기존 코스를 함께 바꾸지는 않습니다.

`buildTrack`은 제어점을 폐곡선으로 보간하고 길이·누적 거리·도로 폭·출발 위치를 만듭니다. 현재 도로 폭은 18m이며, `beginner`와 그 외 코스는 서로 다른 보간 방식을 사용합니다. 새 코스는 기본적으로 후자의 방식을 따릅니다. 곡선이 제어점과 정확히 같다고 가정하지 말고 **생성된 경로**를 확인합니다. 중복점, 급격한 꺾임, 서로 너무 가까운 구간이나 겹치는 도로는 `nearestTrack`의 판정과 화면에 영향을 줄 수 있습니다.

`sampleTrack`과 `nearestTrack`은 도로 생성, 물리, 출발·복귀 위치와 진행 판정에 함께 사용됩니다. `startDistance`를 바꾼다면 출발선과 네 자리 그리드, 마지막 코너에서 출발선으로 돌아오는 구간을 함께 확인합니다. 진행 판정은 거리와 체크포인트를 사용하므로 역주행이나 지름길로 랩이 올라가지 않는지도 확인합니다.

## 2. 선택 화면과 서버 연결

- `public/main.js`의 코스 선택 화면과 미니맵은 `TRACKS`를 읽어 구성합니다. 새 코스가 혼자 연습과 방 만들기 양쪽에 표시되는지, 길이·랩 선택·미니맵이 맞는지 확인합니다.
- `public/i18n.js`에 코스 이름의 영어 번역을 추가하고 한국어와 영어 화면을 확인합니다.
- `server.js`는 `TRACKS`와 `LAP_OPTIONS`로 코스와 랩 수를 검증하고 방 상태·스냅샷에 전달합니다. 방 생성, 다른 참가자의 입장, 출발, 결과와 재경기에서도 새 코스 ID와 랩 수가 유지되는지 확인합니다. 잘못된 ID와 랩 수는 거부되어야 합니다.
- 기본 `LAPS`는 3입니다. `createCar`, `test/race-stability.test.js` 등 기본 랩 수를 사용하는 곳과 새 코스의 `LAP_OPTIONS`가 호환되는지 확인하고, 3랩을 지원하지 않는 설계라면 호출부와 테스트를 함께 수정합니다.
- `README.md`와 `README.ko.md`의 코스 수, 이름, 랩 선택 설명도 실제 UI에 맞게 고칩니다.

## 3. 도로와 풍경

`public/scene.js`의 `buildCourse`는 공유 경로를 샘플링해 도로, 커브, 출발선과 부스트 패드를 그립니다. `public/beach.js`의 `trackPropsLayout` 등은 풍경과 소품을 배치합니다. `beginner`, `technical`, `mandalika`를 직접 비교하는 분기와 기본값을 읽고, 새 코스가 다른 코스 전용 풍경을 실수로 상속하지 않는지 확인합니다. 그래픽 측정과 코스 전환도 `public/scene.js`에서 확인합니다.

기존 모델과 소품을 우선 재사용합니다. 새 에셋이 필요하다면 실제 로더 경로와 목록, 라이선스·출처 고지를 함께 갱신합니다. 화면에만 있는 장식과 실제 주행 충돌 판정을 혼동하지 말고, 도로의 보이는 경계와 공유 물리의 경계가 일치하는지 확인합니다.

## 4. 자동 검증

Node.js 24에서 `npm ci`로 의존성을 설치하고, 변경한 영역에 맞춰 다음 검사를 먼저 실행합니다.

```sh
node --test test/game.test.js test/race-stability.test.js test/cornering.test.js
node --test test/beach.test.js test/depth-surfaces.test.js test/scenery-quality.test.js
node --test test/server.test.js test/client.test.js test/i18n.test.js
npm test
```

서버·클라이언트 통합 테스트는 임시 로컬 포트가 필요합니다. 포트 바인딩이 환경에서 차단되면 테스트 실패와 애플리케이션 결함을 구분해 기록합니다.

새 코스의 랩 선택별 시작·체크포인트·완주, 잘못된 코스/랩 거부, 복귀와 역주행, 벽·차량 충돌 및 기존 코스 회귀를 확인하는 테스트를 추가하거나 갱신합니다. 기존 테스트 중 일부는 코스 ID와 랩 목록을 직접 열거하므로 새 코스가 자동으로 포함된다고 가정하지 않습니다. `test/race-stability.test.js`는 등록된 코스와 각 차량으로 물리 주행을 시도하지만, 고정된 운전 전략의 결과입니다. 통과만으로 사람의 주행감이나 밸런스가 증명되지는 않습니다.

필요하면 아래 명령으로 차종별 조향 측정과 코스별 자동 주행 결과를 비교합니다. 결과는 Git에서 제외된 `.cache/`에 저장됩니다.

```sh
node tools/qa/cornering-balance.mjs current
```

`node tools/qa/change-server-check.mjs --dnf`와 `--dnf --auto-timeout`은 기본 코스에서 실제 WebSocket으로 완주·재경기 흐름을 확인하는 느린 검사입니다. 새 코스 전용 다중 사용자 검증을 대신하지 않습니다.

## 5. 실제 화면과 플레이 확인

로컬 서버를 실행해 새 코스의 연습과 방 만들기를 직접 확인합니다. 출발선·4대 그리드·랩 수·부스트 패드·미니맵·결과 화면을 살펴보고, 코스를 한 바퀴 이상 주행하며 도로/풍경 겹침, 가려지는 표지, 좁은 헤어핀과 복귀 위치를 확인합니다. 주간·야간과 그래픽 품질도 살펴봅니다.

가능하면 여러 브라우저 또는 실제 LAN의 서로 다른 PC로 방 참가, 출발, 충돌, 완주, 관전과 재경기를 확인합니다. 자동 주행, 같은 PC의 여러 브라우저, 여러 실제 PC의 LAN 주행은 각각 다른 검증입니다. 수행하지 못한 단계는 완료로 표시하지 말고 결과와 한계를 함께 기록합니다.
